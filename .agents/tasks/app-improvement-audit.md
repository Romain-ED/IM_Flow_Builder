# App improvement audit

## Summary
Highest impact: make channel/platform branding and interaction states more faithful, harden Live RCS deployment/runtime recovery, and add an end-to-end accessibility/smoke gate. The simulator is well-layered and heavily unit-tested, but the visible phone chrome still contains generic or inert controls and production storage settings can contradict the documented durability requirement.

## Evidence
- **Brand fidelity (P1):** `src/components/controls/ChannelSelector.tsx` fills RCS/WhatsApp buttons with brand colors, but `BrandIcon.tsx` uses generic Lucide speech bubbles for both channels. Replace with reviewed official/approved marks and add accessible text/tooltips; keep contrast tests for active/inactive states. `src/components/controls/BrandIcon.tsx`, `src/components/controls/ChannelSelector.tsx`.
- **Platform UX (P1):** iOS/Android are modeled in `src/schema/platform.ts` and shared-link tests cover switching, but the audit should ensure the visible selector communicates platform identity consistently and persists/loads it without surprising shared-link behavior (`src/store/sharedLinkMode.test.tsx`).
- **Inert controls (P1):** `WhatsAppHeader.tsx` renders Back, video-call, and overflow buttons without handlers; RCS call/video controls are likewise inert, while only some controls show a toast. Either implement a consistent demo feedback state or remove/disable unavailable actions. `src/channels/whatsapp/WhatsAppHeader.tsx`, `src/channels/rcs/RcsHeader.tsx`.
- **Deployment reliability (P1):** docs require durable Vonage storage via `LIVE_RCS_STORE_PATH` + `LIVE_RCS_STORAGE_DURABLE=true`, but `vcr.yml` declares neither environment variable. A redeploy can therefore lose session continuity or fail configuration unexpectedly. Align `vcr.yml`, `server/liveDemo.js:getLiveDemoConfig`, and `docs/LIVE_RCS_DEMO.md`.
- **Accessibility (P2):** there are good ARIA patterns (`App.tsx`, `Carousel.tsx`), but phone overlays and image viewer should gain focus management/escape handling, and automated keyboard checks should cover radios, dialogs, composer, chips, and disabled historical actions. Add Playwright axe-equivalent/manual keyboard smoke coverage; no browser E2E suite is apparent in the inspected test inventory.
- **Performance/maintainability (P2):** `vite.config.ts` precaches up to 5 MiB assets and all bundled files; add a bundle/PWA-size budget and lazy-load heavy Manual/debug/live pages. Keep pure engine/channel boundaries and extend colocated tests rather than adding UI conditionals.

## Conclusions and recommendations
Prioritize branding + actionable header states first because they directly affect demo credibility and the original channel-button request. Next fix VCR manifest durability and add a startup/readiness check that distinguishes configured, ephemeral, and durable modes. Then add targeted browser smoke tests for channel/platform selection, shared-link read-only behavior, responsive compare mode, keyboard dialogs, and a fake Live RCS session. Validate with `npx tsc -b && npm run build && npm test && npx oxlint .`; use the documented Playwright visual pass for UI-visible changes.
